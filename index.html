ACADEMIC SUBMISSION

Mobile Banking Application

Release, Performance and User Acceptance Testing

Subject: Software Engineering
Assignment: 2
Team: 7

Primary Objective: Demonstrate end-to-end software quality assurance for a fintech mobile banking system covering Release Smoke Testing, Concurrency Performance Load Testing, Alpha Verification, Beta Community Feedback, and Formal UAT.

Architecture: Client-side Single Page Application (SPA) leveraging localStorage persistence and real-time Chart.js visual analytics.

5 Comprehensive Testing Types Implemented

1. Release Testing

Automated regression test suite verifying core banking workflows (Login, Balance, Transfer, Bills, Ledger) before production deployment.

2. Performance Testing

Simulated concurrent load tiers (10, 50, 100, 200 users) measuring response time latency (ms), TPS throughput, and SLA compliance.

3. Alpha Testing

Internal white-box & boundary scenarios evaluating input sanitization, floating point precision, overdraft limits, and corrupt state recovery.

4. Beta Testing

End-user cohort evaluation measuring usability, UI clarity, navigation smoothness, and interactive tester feedback ratings.

5. User Acceptance Testing (UAT)

Business stakeholder validation matrix verifying functional requirements against expected banking outcomes with formal sign-off.

6. Detailed Test Scenarios

In-depth input, expected output, actual output, duration, and execution trace proof for Login, Balance Enquiry, and Fund Transfers.

System Architecture & Tech Stack

Frontend Layer:

HTML5 Semantic Elements, Modern CSS3 with Custom Properties, CSS Grid, Flexbox, FontAwesome 6 icons.

Logic & State Layer:

Pure Vanilla JavaScript (ES6+), Modular IIFE Pattern, Event-Driven Router, Chart.js for Load Analytics.

Storage & Security:

Browser localStorage persistence, zero external dependency or paid banking APIs, simulated atomic double-entry bookkeeping.
